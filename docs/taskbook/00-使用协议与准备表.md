# 第 00 章：使用协议与开工准备表

本章不创建源码、不初始化 Git。目标是把不可由任务书替你决定的个人事实一次填清，并建立安全操作习惯。

## 00-01 建立纸面执行记录

预计时间：15 分钟。

1. 在电脑上新建一个不进入本项目 Git 的个人笔记，命名为“个人网站施工记录”。可以使用纸质本，也可以使用本地笔记软件。
2. 写下今天日期、当前章节 `00-01` 和项目目录 `D:\CODEkingdom\rodolfoiolo`。
3. 建立四个固定小节：`真实输出`、`错误与修复`、`我理解的调用链`、`待替换个人内容`。
4. 以后任务书要求记录秘密时，只记录“已创建”和保存位置，不记录秘密本身。

为什么：Git 记录代码为什么变化，施工记录保存你怎样理解和排错。企业工程能力来自可复盘过程，不来自把工具堆进仓库。

验收：你能在笔记中找到上述四个小节。

## 00-03 识别秘密

预计时间：20 分钟。

以下内容永远不能进入 Git、Markdown、聊天、Issue、PR 描述、日志或截图：

- PostgreSQL 生产密码；
- JWT 私钥；
- Refresh Token、Access Token 和完整 Cookie；
- GitHub Personal Access Token；
- ECS SSH 私钥；
- 阿里云 AccessKey ID 和 AccessKey Secret；
- 评论访客签名密钥；
- 真实备份文件。

允许提交的是 `.env.example`、公钥、Secret 名称、生成命令和脱敏示例。第 02 章会建立 `.gitignore`，第 13 章会运行秘密扫描。

在施工记录写一句：`真实秘密只进入密码管理器、GitHub/云平台 Secret 或本机被忽略文件。`

验收：能解释为什么 `.env.example` 可以提交而 `.env` 不可以。

## 00-04 理解项目边界

预计时间：30 分钟。

本项目采用模块化单体，而不是微服务：

```text
Browser
  -> Nginx/TLS
     -> exported Next.js files
     -> /api/v1 -> Go/Echo
                    -> Handler
                    -> Service
                    -> Repository
                    -> PostgreSQL
                    -> OSS (media only)
```

各层只承担一种职责：

| 层 | 可以做 | 不可以做 |
|---|---|---|
| OpenAPI | 定义 HTTP 输入、输出和错误 | 写业务实现 |
| Handler | HTTP/DTO 转换、调用 Service | 写 SQL、决定事务 |
| Service | 业务规则、权限、事务边界 | 依赖 Echo Context |
| Repository | 参数化 SQL、行映射 | 生成 HTTP 响应 |
| Web public | 构建期读取公开 API、输出静态 HTML | 请求期依赖 Node 服务 |
| Web admin | 浏览器运行的受保护管理界面 | 把 Refresh Token 放进 JS |
| Nginx | TLS、静态文件、反向代理、限速 | 承担业务授权 |

在施工记录中，用自己的话写三句话：为什么本项目不用 Kubernetes、为什么公共页静态导出、为什么 Handler 不写 SQL。

## 00-05 明确分阶段交付

预计时间：15 分钟。

开发顺序不是“一口气写完所有代码”：

1. MVP：公开内容、API、SEO、HTTPS、可回滚部署；内容先用管理员 CLI 或受保护 API 写入。
2. Admin：补齐可视化管理后台。
3. Experience：加入你亲手制作的风景素材和滚动动效。
4. Interaction：加入媒体、点赞、评论和审核。
5. Production hardening：完整测试、安全、性能、备份恢复和事故演练。

每个阶段都能运行和验收。这样遇到问题时只排查当前垂直切片，而不是面对几十个同时未完成的模块。

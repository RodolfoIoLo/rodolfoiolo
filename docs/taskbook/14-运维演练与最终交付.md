# 第 14 章：运维演练与最终交付

本章不再增加产品功能。目标是证明你能发布、观察、备份、恢复、回滚和处置事故，并把仓库标记为可复现的 `v1.0.0`。

## 14-01 定义生产目标

把以下目标写入项目 Issue `Production readiness v1.0`：

| 指标     | v1.0 目标                                 |
| -------- | ----------------------------------------- |
| 可用性   | 月度 99.5%，计划维护不计入                |
| RPO      | 最多丢失 24 小时数据库数据                |
| RTO      | 2 小时内恢复公共站点和 API                |
| 备份保留 | 每日 7 份、每周 4 份、每月 6 份           |
| 日志保留 | 应用与 Nginx 14 天                        |
| 发布回滚 | 10 分钟内切回上一静态 release 与 API 镜像 |
| 告警     | 连续 3 次外部健康检查失败后通知           |

这是个人项目可负担的 SLO，不宣称金融级高可用。每次演练记录开始时间、结束时间、证据和偏差。

## 14-03 创建数据库备份脚本

创建 `scripts/backup-db.sh`，文件全文：

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
umask 077

ROOT="${DEPLOY_ROOT:-/opt/personal-site/repository}"
BACKUP_ROOT="${BACKUP_ROOT:-/opt/personal-site/backups}"
ENV_FILE="$ROOT/.env.production"
[[ -f "$ENV_FILE" ]] || { echo "missing $ENV_FILE" >&2; exit 1; }
install -d -m 700 "$BACKUP_ROOT"
set -a
# shellcheck disable=SC1090
source "$ENV_FILE"
set +a

timestamp="$(date -u +%Y%m%dT%H%M%SZ)"
target="$BACKUP_ROOT/personal-site-$timestamp.sql.gz"
checksum="$target.sha256"
cd "$ROOT"
docker compose --env-file .env.production -f compose.prod.yml exec -T postgres \
  pg_dump --format=plain --no-owner --no-privileges --clean --if-exists \
  --username "$POSTGRES_USER" --dbname "$POSTGRES_DB" | gzip -9 > "$target"
gzip -t "$target"
sha256sum "$target" > "$checksum"
chmod 600 "$target" "$checksum"
find "$BACKUP_ROOT" -maxdepth 1 -type f -name 'personal-site-*.sql.gz*' -mtime +35 -delete
printf '%s\n' "$target"
```

删除命令的目标固定为 `BACKUP_ROOT` 且只匹配备份文件。第一次执行前在 ECS 运行 `realpath /opt/personal-site/backups`，必须位于 `/opt/personal-site/`。

## 14-04 创建隔离恢复脚本

创建 `scripts/restore-drill.sh`，文件全文：

```bash
#!/usr/bin/env bash
set -Eeuo pipefail

[[ $# -eq 1 ]] || { echo "usage: $0 /absolute/backup.sql.gz" >&2; exit 2; }
backup="$(realpath "$1")"
backup_root="$(realpath "${BACKUP_ROOT:-/opt/personal-site/backups}")"
[[ "$backup" == "$backup_root"/* ]] || { echo "backup is outside $backup_root" >&2; exit 2; }
[[ -f "$backup" && -f "$backup.sha256" ]] || { echo "backup or checksum missing" >&2; exit 2; }
cd "$backup_root"
sha256sum --check "$(basename "$backup").sha256"
gzip -t "$backup"

name="personal-site-restore-$RANDOM-$RANDOM"
password="$(openssl rand -hex 24)"
cleanup() { docker rm -f "$name" >/dev/null 2>&1 || true; }
trap cleanup EXIT
docker run -d --name "$name" -e POSTGRES_DB=restore_probe -e POSTGRES_USER=restore_probe -e POSTGRES_PASSWORD="$password" postgres:16.9-bookworm >/dev/null
for attempt in {1..30}; do docker exec "$name" pg_isready -U restore_probe -d restore_probe >/dev/null 2>&1 && break; sleep 1; done
gunzip -c "$backup" | docker exec -i "$name" psql -v ON_ERROR_STOP=1 -U restore_probe -d restore_probe >/dev/null
docker exec "$name" psql -v ON_ERROR_STOP=1 -U restore_probe -d restore_probe -c 'SELECT COUNT(*) AS users FROM users; SELECT COUNT(*) AS articles FROM articles; SELECT COUNT(*) AS migrations FROM schema_migrations;'
echo "isolated restore drill passed"
```

恢复永远进入临时 PostgreSQL 容器，不连接生产数据库。生产恢复必须在事故指挥人明确批准、维护窗口开启并再次备份现状后执行。

## 14-05 创建原子部署脚本

创建 `scripts/deploy.sh`，文件全文：

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
umask 027

[[ $# -eq 1 && "$1" =~ ^[0-9a-f]{40}$ ]] || { echo "usage: $0 <40-character-git-sha>" >&2; exit 2; }
sha="$1"
root="${DEPLOY_ROOT:-/opt/personal-site/repository}"
cd "$root"
exec 9>/var/lock/personal-site-deploy.lock
flock -n 9 || { echo "another deployment is running" >&2; exit 1; }
[[ -f .env.production ]] || { echo "missing production environment" >&2; exit 1; }
set -a
# shellcheck disable=SC1091
source .env.production
set +a

git fetch --prune origin main
git merge-base --is-ancestor "$sha" origin/main || { echo "release is not on origin/main" >&2; exit 1; }
git diff --quiet && git diff --cached --quiet || { echo "repository has local changes" >&2; exit 1; }
git checkout --detach "$sha"
export RELEASE_SHA="${sha:0:12}"
release_dir="$root/releases/$RELEASE_SHA"
[[ ! -e "$release_dir" ]] || { echo "release already exists" >&2; exit 1; }

"$root/scripts/backup-db.sh" >/dev/null
docker compose --env-file .env.production -f compose.prod.yml build --pull api
docker compose --env-file .env.production -f compose.prod.yml up -d postgres
docker compose --env-file .env.production -f compose.prod.yml run --rm migrate
docker compose --env-file .env.production -f compose.prod.yml up -d api
for attempt in {1..30}; do docker compose --env-file .env.production -f compose.prod.yml exec -T api /app/api --healthcheck && break; sleep 2; done
docker compose --env-file .env.production -f compose.prod.yml exec -T api /app/api --healthcheck

docker run --rm --network personal-site_backend \
  --user "$(id -u):$(id -g)" \
  -e HOME=/tmp/home \
  -e CONTENT_API_BASE_URL=http://api:8080/api/v1 \
  -e NEXT_PUBLIC_API_BASE_URL="https://$SITE_DOMAIN/api/v1" \
  -e NEXT_PUBLIC_SITE_URL="https://$SITE_DOMAIN" \
  -v "$root:/workspace" -w /workspace node:24.14.0-bookworm \
  bash -lc 'mkdir -p "$HOME" && corepack install --global pnpm@11.19.0 && pnpm install --frozen-lockfile && pnpm --dir web build'

install -d -m 755 "$release_dir/web"
cp -a web/out/. "$release_dir/web/"
test -s "$release_dir/web/index.html"
test -s "$release_dir/web/rss.xml"
test -s "$release_dir/web/sitemap.xml"
ln -sfn "$RELEASE_SHA" releases/current.next
mv -Tf releases/current.next releases/current
docker compose --env-file .env.production -f compose.prod.yml up -d --force-recreate nginx
curl --fail --silent --show-error --retry 5 "https://$SITE_DOMAIN/api/v1/readyz" >/dev/null
curl --fail --silent --show-error --retry 5 "https://$SITE_DOMAIN/" >/dev/null
printf 'deployed %s\n' "$sha"
```

数据库迁移只向前。静态目录先完整写入新 SHA，再用同文件系统 `mv` 原子替换 symlink。外部冒烟失败时脚本退出，执行 14-06 回滚。

## 14-06 创建回滚脚本

创建 `scripts/rollback.sh`，文件全文：

```bash
#!/usr/bin/env bash
set -Eeuo pipefail

[[ $# -eq 1 && "$1" =~ ^[0-9a-f]{12}$ ]] || { echo "usage: $0 <12-character-release>" >&2; exit 2; }
release="$1"
root="${DEPLOY_ROOT:-/opt/personal-site/repository}"
cd "$root"
exec 9>/var/lock/personal-site-deploy.lock
flock -n 9 || { echo "deployment lock is busy" >&2; exit 1; }
[[ -s "releases/$release/web/index.html" ]] || { echo "release is incomplete" >&2; exit 1; }
docker image inspect "personal-site-api:$release" >/dev/null
set -a
# shellcheck disable=SC1091
source .env.production
set +a
export RELEASE_SHA="$release"
ln -sfn "$release" releases/current.next
mv -Tf releases/current.next releases/current
docker compose --env-file .env.production -f compose.prod.yml up -d --no-build --force-recreate api nginx
curl --fail --silent --show-error --retry 5 "https://$SITE_DOMAIN/api/v1/readyz" >/dev/null
curl --fail --silent --show-error --retry 5 "https://$SITE_DOMAIN/" >/dev/null
printf 'rolled back to %s; database migrations were not reversed\n' "$release"
```

回滚 API 代码必须与当前向前迁移后的数据库兼容，这是“expand -> migrate -> contract”迁移纪律。破坏性删列至少跨两个版本完成。

## 14-07 创建外部健康检查脚本

创建 `scripts/smoke-production.ps1`，文件全文：

```powershell
[CmdletBinding()]
param([Parameter(Mandatory)][string]$Domain)
$ErrorActionPreference = 'Stop'
$base = "https://$Domain"
$checks = @('/', '/articles/', '/projects/', '/rss.xml', '/sitemap.xml', '/api/v1/healthz', '/api/v1/readyz')
foreach ($path in $checks) {
    $response = Invoke-WebRequest "$base$path" -MaximumRedirection 3
    if ($response.StatusCode -ne 200 -or $response.RawContentLength -eq 0) { throw "$path failed" }
    [pscustomobject]@{ Path = $path; Status = $response.StatusCode; Bytes = $response.RawContentLength }
}
$headers = (Invoke-WebRequest "$base/").Headers
foreach ($name in @('Strict-Transport-Security', 'Content-Security-Policy', 'X-Content-Type-Options')) {
    if (-not $headers.ContainsKey($name)) { throw "Missing $name" }
}
```

## 14-08 安装定时备份和磁盘保护

```bash
$ cd /opt/personal-site/repository

$ sudo systemctl edit --force --full personal-site-backup.service
```

填入：

```ini
[Unit]

Requires=docker.service
After=docker.service

[Service]
Type=oneshot
User=deploy
Environment=DEPLOY_ROOT=/opt/personal-site/repository
Environment=BACKUP_ROOT=/opt/personal-site/backups
ExecStart=/opt/personal-site/repository/scripts/backup-db.sh
```

若 ECS 登录用户不是 `deploy`，把 `User=` 精确替换为第 00 章 `ECS_SSH_USER`。创建 timer：

```bash
$ sudo systemctl edit --force --full personal-site-backup.timer
```

```ini
[Unit]
Description=Daily personal-site backup

[Timer]
OnCalendar=*-*-* 02:20:00
RandomizedDelaySec=20m
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
$ sudo systemctl daemon-reload
$ sudo systemctl enable --now personal-site-backup.timer
$ sudo systemctl start personal-site-backup.service
$ sudo systemctl status personal-site-backup.service --no-pager
$ sudo systemctl list-timers personal-site-backup.timer
```

把每日备份通过加密 rclone 配置同步到与 ECS 不同地域的私有 OSS Bucket。rclone 配置文件权限必须 600，RAM 权限只允许备份前缀写入与读取；同步后在 OSS 生命周期中设置 7/30/180 天分层保留。服务器本地备份不是异地备份。

## 14-11 演练三类事故

### A：API 进程退出

```bash
$ docker compose --env-file .env.production -f compose.prod.yml kill api
$ docker compose --env-file .env.production -f compose.prod.yml ps
$ sleep 15
$ docker compose --env-file .env.production -f compose.prod.yml ps
```

验证 restart policy 拉起 API；公共静态页始终可读，互动短暂失败后恢复。

### B：数据库不可用

```bash
$ docker compose --env-file .env.production -f compose.prod.yml stop postgres
$ curl -i "https://$SITE_DOMAIN/api/v1/readyz"
$ curl -i "https://$SITE_DOMAIN/"
$ docker compose --env-file .env.production -f compose.prod.yml start postgres
```

预期 readyz 503、静态首页 200。数据库恢复后 readyz 回到 200。

### C：错误静态 release

不要修改生产 release 文件。把 `current` 切到一份已知旧 release，确认版本标识变化，再使用 `rollback.sh` 恢复目标 release。演练不伪造数据损坏。

## 14-12 建立事故响应顺序

事故发生时严格按以下顺序：

1. **确认**：外部复现、记录 UTC 开始时间和影响面；
2. **止血**：回滚、关闭写入口或切维护页，优先恢复服务；
3. **保全证据**：保存容器状态、最近 500 行脱敏日志、release、镜像、迁移版本；
4. **修复**：从受保护分支走 PR 和必需 CI，不直接在服务器编辑源码；
5. **验证**：外部 smoke、关键业务、日志和指标；
6. **复盘**：48 小时内写无责复盘，包含时间线、根因、促成因素、检测缺口和有 owner/日期 的行动项。

不得在 Issue 粘贴 `.env.production`、Cookie、Authorization、数据库 URL、AccessKey 或私钥。

## 14-13 清理 release 的安全规则

只在至少保留当前和前两个健康 release 后清理。先输出候选绝对路径并人工核对它们均位于 `/opt/personal-site/repository/releases/`；不得用根据空变量拼接的 `rm -rf`。API 镜像同样保留当前和前两个标签。数据库卷、`secrets`、`uploads`、`certbot` 和 `backups` 永远不属于 release 清理目标。

## 14-16 创建 v1.0.0 Release

先确认 main 的所有 required checks 通过且生产正在运行这个 commit：


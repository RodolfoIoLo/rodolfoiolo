这是一套按真实开发时间顺序展开的施工说明书。你不需要独立设计架构或从空白文件编写代码；你需要逐条执行命令、逐个创建文件、阅读解释、观察真实输出，并在检查点停下来确认结果。

“照做”不等于跳过理解。每个步骤都包含目的、输入、动作、预期结果、失败处理和 Git 记录。遇到实际输出与预期不同，停止当前编号，不继续粘贴后续命令。

## 不允许跳过的规则

1. 只从仓库根目录执行标有 `PS>` 的命令；`PS>` 是提示符，不要输入。
2. 一个编号未通过验证时，不进入下一个编号。
3. 代码块标注“文件全文”时，先清空目标文件，再完整写入，不能和旧内容拼接。
4. 标注“命令生成”的文件不手写；运行固定命令后提交生成结果。
5. 标注“本地秘密”的真实值不写进文档、聊天、Issue、提交或终端截图。
6. 每次 `git add` 都使用任务书列出的具体路径，不使用 `git add .`。
7. 不修改 `main` 上的业务文件；每个任务在指定分支完成，经 PR 合并。
8. 不以“页面能打开”代替验收；测试、契约、错误路径、可访问性和回滚同属完成条件。
9. 不提前安装 Redis、Kubernetes、Elasticsearch 或微服务组件。指标达到任务书中的引入门槛后，另写 ADR。
10. 任务书没有出现“其余类似”“自行补充”“TODO 后完成”等省略语。若发现此类表述，视为任务书缺陷，停止执行并修订文档。

## 文件内容边界

任务书保证给出所有人工维护文本文件的完整内容。以下三类文件不把字节全文粘贴进 Markdown，但创建动作仍完整说明：

- 包管理器、代码生成器和框架生成物：给出精确版本、完整命令、输出路径和漂移检查；
- 图片、字体、图标和 favicon 等二进制文件：给出制作步骤、尺寸、格式、压缩命令、许可记录和 SHA-256；
- 密码、私钥、Token 和云密钥：给出本地生成命令、权限、Secret 名称和验证方法，永远不提供固定真实值。

这是供应链边界，不是遗漏。人工维护文件若没有全文，则该章节不能标记完成。

## 每个编号的固定闭环

```text
Read      确认工作目录、分支、前置检查
Change    只执行当前编号列出的动作
Verify    运行自动验证并核对人工结果
Record    查看 diff，提交一个职责清晰的 commit
Integrate Push、PR、自审、CI、合并、删除分支
Reflect   用三句话记录学到的边界、失败路径和取舍
```

## 最终产品范围

公共站点包含首页、文章、项目、归档、关于、RSS、Sitemap、SEO、主题和沉浸式动态风景背景。后台包含登录、仪表盘、文章、项目、分类、标签、评论审核、媒体和站点设置。互动包含匿名点赞和审核后评论。

工程包含 OpenAPI-first、Go 分层、PostgreSQL 迁移、静态公共站点、Docker Compose、Nginx/TLS、GitHub Actions、备份恢复、回滚、日志脱敏、安全头、限流、单元/集成/契约/E2E 测试和性能预算。

## 完成定义

只有同时满足以下条件，项目才算完成：

- 从空目录按本任务书演练，不依赖聊天中未写入文档的信息；
- 所有人工文件都能在章节或明确的“替换全文”步骤找到；
- Go、TypeScript、Lint、单元、集成、契约和 E2E 门禁通过；
- 数据库能执行 `up -> down -> up`，生产遵守只向前迁移；
- 公共内容存在于导出的 HTML，RSS/Sitemap/结构化数据有效；
- 键盘、移动端和减少动效模式可用；
- 生产发布、回滚、备份和隔离恢复演练有记录；
- Git 历史按任务书提交，`main` 分支保护和 PR 规则启用；
- 没有测试密钥、占位域名、临时账号、TODO、501 或未授权素材进入发布包。

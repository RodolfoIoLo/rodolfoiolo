本章建立跨语言仓库的格式、忽略、环境模板、包管理、协作规则和最小 CI。所有文件均从仓库根目录计算路径。

## 02-04 固定 Node 和 pnpm

创建 `.node-version`：

文件作用:

- 声明 Node.js 版本,团队成员和 CI 都会使用该版本,避免不同版本导致的构建失败或行为不一致
- 配合 Corepack 和 pnpm 固定包管理器版本,保证依赖安装一致性

告诉开发环境"用哪个Node版本"

```text
24.14.0
```

创建 `.npmrc`：

文件作用:

- 固定 pnpm 版本,团队成员和 CI 都会使用该版本,避免不同版本导致的依赖解析差异
- 配置 pnpm 的行为,如严格依赖、保存精确版本、关闭自动安装 peer 依赖等,保证团队和 CI 的一致性

告诉 npm/pnpm “安装依赖时按什么规则做”

```ini
engine-strict=true
save-exact=true
strict-peer-dependencies=true
auto-install-peers=false
```

创建 `pnpm-workspace.yaml`：

文件作用:

- 声明哪些目录是 pnpm 工作区,方便统一安装依赖和运行

告诉 pnpm “这是不是 monorepo，哪个目录是工作包”

```yaml
packages:
  - web
```

创建根目录 `package.json`：

文件作用:

- 声明 Node.js 和 pnpm 版本,团队成员和 CI 都会使用
- 声明根目录的开发依赖和脚本,方便统一格式化和文档检查
- 通过 `pnpm install` 生成 `pnpm-lock.yaml`,锁定所有依赖版本,保证团队和 CI 的一致性

告诉Node/pnpm:这个项目有哪些依赖,脚本,版本要求"

```json
{
  "name": "personal-site-workspace",
  "version": "0.0.0",
  "private": true,
  "packageManager": "pnpm@11.19.0",
  "engines": {
    "node": "24.14.0",
    "pnpm": "11.19.0"
  },
  "scripts": {
    "format": "prettier --write .",
    "format:check": "prettier --check .",
    "lint:docs": "markdownlint-cli2 \"docs/**/*.md\" \"#docs/archive/**\""
  },
  "devDependencies": {
    "markdownlint-cli2": "0.20.0",
    "prettier": "3.6.2"
  }
}
```

创建 `.prettierrc.json`：

文件作用:

- 声明 Prettier 的格式化规则,团队成员和 CI 都会使用,保证代码风格一致
- 配置 Prettier 的行为,如行宽、引号、尾随逗号、换行等,保证团队和 CI 的一致性

告诉Prettier"代码怎么格式化"

```json
{
  "printWidth": 100,
  "singleQuote": true,
  "trailingComma": "all",
  "proseWrap": "preserve"
}
```

创建 `.prettierignore`：

文件作用:

- 声明哪些文件或目录不需要 Prettier 格式化,避免格式化生成文件、依赖包、日志等无关内容
- 保证团队和 CI 的一致性,避免格式化无关内容导致的冲突或误报

告诉 Prettier “哪些文件不要被格式化”

```text
.next
out
node_modules
coverage
playwright-report
test-results
pnpm-lock.yaml
server/generated
web/types/openapi.d.ts
docs/api/openapi.yaml
```

安装根工具并生成锁文件：

```powershell
PS> pnpm install #读取package.jjson里的依赖声明,下载对应的包到node_modules,安装所有devDependencies,按工作区规则处理monorepo,生成/更新lock文件
PS> pnpm exec prettier --version
PS> pnpm exec markdownlint-cli2 --version
```

`pnpm-lock.yaml` 是命令生成文件，必须提交，不手工编辑。若某个精确依赖版本不存在，停止并核对任务书基线，不擅自改成 `latest`。

## 02-07 创建协作文档

创建根目录 `README.md`：

```markdown
# Personal Site

A content-rich personal website built as a modular monolith with a statically exported Next.js public site, a Go API, PostgreSQL, and an authenticated admin interface.

## Status

The repository is being built from zero by following `docs/taskbook/README.md`.

## Architecture

- `web/`: Next.js public site and admin UI
- `server/`: Go API and database migrations
- `docs/api/openapi.yaml`: source of truth for the HTTP contract
- `docs/`: decisions, taskbook, design, and operations
- `nginx/`: production edge configuration
- `scripts/`: repeatable development and operations commands

## Local prerequisites

- Node.js 24.14.0
- pnpm 11.19.0
- Go 1.25.3
- Docker Engine with Compose

Do not invent setup steps from this short README. Use the taskbook.
```

创建 `CONTRIBUTING.md`：

```markdown
# Contributing

## Workflow

1. Update `main` with `git pull --ff-only`.
2. Create one `feat/*`, `fix/*`, `docs/*`, `test/*`, or `chore/*` branch.
3. Keep each commit focused and use Conventional Commit prefixes.
4. Run the checks listed in the current taskbook unit.
5. Open a pull request, review the complete diff, and wait for required checks.
6. Squash merge, update local `main`, and delete the merged branch.

## Contract first

HTTP changes begin in `docs/api/openapi.yaml`. Regenerate Go and TypeScript artifacts and commit contract, generated code, implementation, and tests in reviewable commits. Generated files are never edited manually.

## Database changes

Published migration files are immutable. Add a new up/down pair, verify up/down/up locally, and keep production migrations forward-only.

## Definition of done

A change is done only when behavior, failure paths, tests, documentation, security impact, deployment impact, and rollback are reviewed.
```

创建 `SECURITY.md`：

```markdown
# Security Policy

## Reporting

Do not open public issues for suspected vulnerabilities. Contact the repository owner privately through the email listed in the GitHub profile.

## Secret handling

Never commit passwords, tokens, cookies, private keys, cloud credentials, production data, or backups. Use ignored local files, GitHub Actions secrets, and cloud secret stores. Logs and test fixtures must contain synthetic data only.

## Supported version

Only the latest release on `main` receives security fixes while this is a single-owner project.
```

## 02-10 创建最小文档 CI

创建 `.github/workflows/ci.yml`：

```yaml
name: CI

on:
  pull_request:
  push:
    branches:
      - main

permissions:
  contents: read

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  repository:
    name: Repository checks
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - name: Check out repository
        uses: actions/checkout@v5

      - name: Set up Node.js
        uses: actions/setup-node@v5
        with:
          node-version-file: .node-version

      - name: Enable Corepack
        run: corepack enable

      - name: Install pnpm
        run: corepack install --global pnpm@11.19.0

      - name: Install workspace tools
        run: pnpm install --frozen-lockfile

      - name: Check formatting
        run: pnpm format:check
```

说明：CI 会在后续章节以“替换全文”方式增加 OpenAPI、Go、PostgreSQL、Web 和 E2E Job。当前不能引用尚不存在的目录。
